Dashboard

Dashboard: командный операционный центр

Что здесь делает SOC-команда

  • Смотрит критичные KPI: открытые кейсы, активные алерты, среднее время расследования.
  • Контролирует дежурства и смены аналитиков.
  • Переходит к проблемным зонам через быстрые ссылки.
  • Отслеживает общую стабильность модулей платформы.
3 / 25
Alerts

Alerts: intake и triage событий

Список алертов: фильтрация, массовое выделение, привязка к существующему кейсу, создание кейса из алертов, bulk delete.
Карточка алерта: контекст, severity/source/tags/owner, быстрые действия, переход к расследованию.
4 / 25
Analyzers / Responders

Run Action: запуск анализаторов и респондеров

Назначение: оператор выбирает observable и шаблон действия (analyzer/responder), выполняет шаг и получает результат прямо в интерфейсе. Это bridge между triage и автоматизацией.

5 / 25
Cases

Cases: единая точка расследования

Основные действия

  • Поиск и фильтры по статусам, критичности, владельцу.
  • Массовые операции над выбранными кейсами.
  • Создание/удаление кейсов, назначение владельцев.
  • Переход в детальную карточку расследования.
6 / 25
Case Tabs I

Case Detail: вкладки расследования (1/3)

Overview: summary, метрики, AI verdict/history, обсуждение и ключевые атрибуты кейса.
Timeline: хронология событий расследования и действий команды.
7 / 25
Case Tabs II

Case Detail: вкладки расследования (2/3)

Tasks: план расследования, ответственность, обязательность шагов, прогресс выполнения.
Observables: IOC/Entities, вердикты, теги, добавление и коррекция в контексте кейса.
8 / 25
Case Tabs III

Case Detail: вкладки расследования (3/3)

Вкладки Attachments, Comments, MITRE, Connectors обеспечивают evidence-менеджмент, техническую атрибуцию и запуск интеграций прямо из кейса.
9 / 25
Communications

Case Communications + Forum

Модуль коммуникаций связывает внутреннее расследование с внешним общением: треды, сообщения, вложения, синхронизация ответов через коннекторы (например, Telegram/Webhook).

10 / 25
Forum

Forum: контекстная переписка по кейсам

Для чего нужен

  • Связь расследования с конкретным обсуждением и участниками.
  • Видимость статуса коммуникаций по каждому кейсу.
  • Единая история сообщений для handoff между сменами.
  • Поддержка файлов и внешних reply sync.
11 / 25
Templates I

Templates: Response Templates (вкладка 1)

Назначение вкладки

  • Создание шаблонов для analyzer/responder действий.
  • Хранение параметризованных шаблонов контента.
  • Повторное использование в Run Action и workflow-нодах.
  • Снижение ручной рутины в incident response.
12 / 25
Templates II

Templates: Case Templates (вкладка 2)

Назначение вкладки

  • Типовые сценарии расследования (playbook style).
  • Предзаполнение severity, тегов, обязательных задач.
  • Унификация качества кейсов между командами и тенантами.
  • Быстрое создание новых кейсов по best practice.
13 / 25
Templates III

Templates: Observable Types (вкладка 3)

Назначение вкладки

  • Каталог типов observables и их форматов.
  • Валидация и нормализация IOC данных.
  • Единый стандарт для enrichment и аналитики.
  • Ускорение интеграций с внешними data sources.
14 / 25
Workflow Studio I

Workflow Studio: визуальный конструктор

n8n-подход: блоки Trigger/Condition/Delay/Analyzer/Responder, редактирование графа, управление draft/published/enabled, тестовый запуск с кнопки.

15 / 25
Workflow Studio II

Workflow Studio: история запусков и надежность

Контроль исполнения workflow

  • История запусков со статусами success/failed.
  • Длительность, timestamp и краткий результат.
  • База для SLA мониторинга по автоматизациям.
  • Порог хранения последних запусков для аудита и отладки.
16 / 25
Connectors

Outbound / Inbound Connectors

Outbound: исходящие действия (уведомления, webhook, интеграционные вызовы, синхронизация коммуникаций).
Inbound: ingest событий из внешних источников, schedule/polling, runtime-статусы, dedup.
17 / 25
Administration I

Administration: вкладки Users и Tenants

Users: создание, роли, команды, админ-права, привязка к тенантам.
Tenants: управление организациями/пространствами, лимиты и настройки доступа.
18 / 25
Administration II

Administration: Achievements и Experience

Achievements: настройка наград и XP за достижение.
Experience: ручные начисления XP пользователям с описанием причин и историей.
19 / 25
Administration III

Administration: API Tokens и Load

API Tokens: выпуск и отзыв токенов с границами доступа для API-автоматизаций.
Load: контроль/нагрузочные контуры и операционные проверки в админском контексте.
20 / 25
Profile

Profile и User Profile

Профили включают персональные данные, достижения, уровень/XP прогресс, метрики расследований и публичную карточку аналитика для командной прозрачности.

Security

Security: две вкладки

Password: смена пароля с подтверждением и проверками.
Sessions: просмотр активных сессий и принудительное завершение.

Executive View

Что важно руководству

Product Depth

Платформа покрывает весь SOC-процесс end-to-end, не только alerting.

Monetization-ready

Multi-tenant + RBAC + API tokens + admin controls = готовая SaaS-модель.

Expansion-ready

Workflow + connectors дают платформенную extensibility для новых интеграций.

Дифференциатор: единый UX для SOC операций + настраиваемые автоматизации + интеграции без выхода из платформы.
